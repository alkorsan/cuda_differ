- fix: Myers diff now produces the same alignment as WinMerge and VS Code for files where Myers' LCS tie-breaking previously matched a trivial line (empty line, whitespace) instead of a meaningful line (e.g. 'delete-only'). Root cause: Myers' O(NP) algorithm and difflib's SequenceMatcher both find *an* LCS, but when multiple valid LCS of the same length exist, they may pick a different one than VS Code's DP algorithm (which uses equality scoring that prefers longer matches). The most visible symptom: INSERT+EQUAL(trivial)+DELETE instead of REPLACE+EQUAL+REPLACE, causing identical lines to be shown as one added + one deleted instead of paired. Fix: added Differ._realign_opcodes() post-processing step in compare() that detects INSERT+EQUAL(trivial)+DELETE (or DELETE+EQUAL(trivial)+INSERT) patterns and merges them into a single REPLACE when the EQUAL block has <= 4 non-whitespace characters total (matching VS Code's removeVeryShortMatchingLinesBetweenDiffs threshold). Then _fancy_replace finds the best line-level alignment within the REPLACE block and naturally matches identical lines (ratio 1.0). This is a no-op for VS Code and patience (they don't produce this pattern). Verified: all four algorithms now produce identical alignment on the test case.
- fix: IndexError in MyersSequenceMatcher.build_matching_blocks when comparing files with long similar lines mixed with short lines (e.g. 3MB HTML with 33k lines). Root cause: both preprocess_discard_nonmatching_lines methods (in MyersSequenceMatcher and InlineMyersSequenceMatcher) had early-return paths that reset aindex/bindex to empty but did NOT reset lines_discarded. When differ._fancy_replace reuses the matcher via set_seq1/set_seq2 (one matcher per replace block, reused for every line pair), a previous long-line pair would set lines_discarded=True, then a later short-line pair (both <= 2 chars after prefix/suffix trimming, with a matching char) would trigger the early return (aindex=[]), but lines_discarded would stay True -- causing build_matching_blocks to enter the discarded-lines branch and access aindex[x] on an empty list. Fix: added self.lines_discarded = False to both early-return paths. This is a latent bug in the upstream Meld code that doesn't manifest in Meld (Meld creates a fresh matcher per diff call and never reuses via set_seq1/set_seq2); it was exposed by the differ plugin's matcher reuse in _fancy_replace. Upstream merges: re-add these two self.lines_discarded = False lines if/when needed.
+ add: new "myers" diff algorithm (default), ported from Meld's MyersSequenceMatcher (https://gitlab.gnome.org/GNOME/meld). Implements the O(NP) sequence comparison algorithm by Sun Wu, Udi Manber, Gene Myers and Webb Miller (1989). Includes two preprocessing optimizations: common prefix/suffix trimming (binary search) and discarding lines that do not appear in the other file (only when worthwhile, i.e. more than 10 lines are discarded). Also includes a post-processing pass that backward-scans matching chunks to combine adjacent blocks that can be merged. Benchmarks on representative inputs show this is the fastest of the four available algorithms: 10-50x faster than the "vscode" DP algorithm, 2-3x faster than "patience" and "difflib" on medium-sized similar files. The "myers" algorithm is now the default; "vscode", "patience" and "difflib" remain available as alternatives.
* change: minimal change to myers.py (added a single super().__init__(isjunk=None, a='', b='', autojunk=False) call inside MyersSequenceMatcher.__init__) so that the inherited difflib.SequenceMatcher attributes (isjunk, autojunk, fullbcount, b2j, bjunk, bpopular) are properly initialized. Without this, reusing the matcher via set_seq1/set_seq2 (which differ._fancy_replace does for character-level detail diffing inside a 'replace' block) would raise AttributeError. The change is backward-compatible with the upstream Meld code path (Meld only uses MyersSequenceMatcher for the main line-level diff via the constructor, so the missing super().__init__() was harmless there) and is needed only because the differ plugin reuses the matcher for character-level diffing. Upstream updates can be merged by re-adding this single super().__init__() call if/when needed.
* change: replaced the previous default 'vscode' with 'myers' in differ.Differ.__init__, in the OPTS_META dropdown (now four entries: myers / vscode / patience / difflib), and in Command.get_config's default. The autojunk config option's comment was updated to mention that Myers also does not support autojunk.
* change: differ._fancy_replace now uses InlineMyersSequenceMatcher (not MyersSequenceMatcher) when diff_algorithm is 'myers'. InlineMyersSequenceMatcher is the Myers variant Meld designed specifically for character-level (inline) diffing: its preprocessing pass uses 3-element k-mers instead of single elements, which makes the preprocessing effective on character sequences (where single characters are rarely unique -- 'a' appears everywhere, so 1-element preprocessing would discard almost nothing). The base MyersSequenceMatcher's 1-element preprocessing is appropriate for the main line-level diff (where each line is usually unique enough), but ineffective for character-level diffing. Benchmarks show InlineMyersSequenceMatcher is 2-4x faster than MyersSequenceMatcher on medium/long lines for character-level diffing, and produces more meaningful character-level diffs. The main line-level diff path (Differ.compare) still uses MyersSequenceMatcher. PatienceSequenceMatcher and DefaultSequenceMatcher are unchanged in _fancy_replace.

+ add: new "vscode" diff algorithm (default), ported from VS Code's diff implementation (https://github.com/microsoft/vscode/tree/main/src/vs/editor/common/diff). Uses dynamic programming (O(MN) LCS with equality scoring and consecutive-diagonal bonus) for files with fewer than 1700 combined lines, and Myers diff (O(ND) with snake optimization) for larger files. Also includes VS Code's heuristic post-processing: optimizeSequenceDiffs (shift/join adjacent diffs to natural boundaries) and removeVeryShortMatchingLinesBetweenDiffs (absorb tiny equal blocks between large changes). The equality scoring (1 + log(1+line_length) for exact matches, 0.99 for whitespace-only matches) and consecutive-diagonal bonus are the key innovations that make this algorithm produce correct alignment on files with many duplicated lines where both patience diff and difflib fail. The "vscode" algorithm is now the default; "patience" and "difflib" remain available as alternatives.

- fix: "Diff with file..." / "Diff with tab..." commands now honor the "autojunk" config option.
