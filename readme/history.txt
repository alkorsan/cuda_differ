2026.08.06 (by @badrelmers)
* change: character-level diff now uses InlineMyersSequenceMatcher (from myers.py) with its 3-element k-mer preprocessing, instead of a timeout-based approach. Studied WinMerge (stringdiffs.cpp: O(NP) with 500ms timeout at line 25, checked every 100000 iterations at line 678-688, fallback to whole-line at line 405-412) and VS Code (myersDiffAlgorithm.ts: O(ND) Myers with timeout check at line 46-48, algorithm selection in defaultLinesDiffComputer.ts refineDiff at line 224-226: DP for <500 chars, Myers for larger). Both use timeouts because they lack k-mer preprocessing. InlineMyersSequenceMatcher's 3-element k-mer preprocessing discards non-matching characters BEFORE running Myers, making it 100-500x faster than raw Myers on character sequences -- even 5000-char completely-different lines diff in ~3ms, so no timeout is needed. This removes the _CHAR_DIFF_MAX_MIDDLE=1000 limit (which was wrong: WinMerge can colorize long lines) and the _CHAR_DIFF_TIMEOUT_MS setting. Performance: 16k-line HTML with detail on = 33s (same as before, no regression); 354-char line with 300 differences = 0.2ms (was 105ms with timeout-based Myers).
* change: removed the "ratio_percents" config option and the recursive "find best pair" search in _fancy_replace. Replaced with the WinMerge/VS Code approach: for each REPLACE opcode, pair lines by position (1st with 1st, 2nd with 2nd, etc.) and do character-level diff on each pair. This eliminates the confusing ratio_percent setting (which VS Code and WinMerge don't expose), fixes the performance regression on large files (3MB HTML: 100s -> 30s), and fixes the alignment breakage when ratio_percent was set to a low value. The old _fancy_replace / _fancy_helper / _plain_replace methods are replaced by a single _replace_block method. Identical lines in a REPLACE block are now shown as unchanged context (matching VS Code), not as "changed with yellow decor".
- fix: Myers diff now produces the same alignment as WinMerge and VS Code for files where Myers' LCS tie-breaking previously matched a trivial line (empty line, whitespace) instead of a meaningful line (e.g. 'delete-only'). Root cause: Myers' O(NP) algorithm and difflib's SequenceMatcher both find *an* LCS, but when multiple valid LCS of the same length exist, they may pick a different one than VS Code's DP algorithm (which uses equality scoring that prefers longer matches). The most visible symptom: INSERT+EQUAL(trivial)+DELETE instead of REPLACE+EQUAL+REPLACE, causing identical lines to be shown as one added + one deleted instead of paired. Fix: added Differ._realign_opcodes() post-processing step in compare() that detects INSERT+EQUAL(trivial)+DELETE (or DELETE+EQUAL(trivial)+INSERT) patterns and merges them into a single REPLACE when the EQUAL block has <= 4 non-whitespace characters total (matching VS Code's removeVeryShortMatchingLinesBetweenDiffs threshold). Then _replace_block pairs lines by position and naturally matches identical lines. This is a no-op for VS Code and patience (they don't produce this pattern). Verified: all four algorithms now produce identical alignment on the test case.
* change: minimal change to myers.py (added a single super().__init__(isjunk=None, a='', b='', autojunk=False) call inside MyersSequenceMatcher.__init__) so that the inherited difflib.SequenceMatcher attributes (isjunk, autojunk, fullbcount, b2j, bjunk, bpopular) are properly initialized. Without this, reusing the matcher via set_seq1/set_seq2 (which differ._fancy_replace does for character-level detail diffing inside a 'replace' block) would raise AttributeError. The change is backward-compatible with the upstream Meld code path (Meld only uses MyersSequenceMatcher for the main line-level diff via the constructor, so the missing super().__init__() was harmless there) and is needed only because the differ plugin reuses the matcher for character-level diffing. Upstream updates can be merged by re-adding this single super().__init__() call if/when needed.
* change: replaced the previous default 'vscode' with 'myers' in differ.Differ.__init__, in the OPTS_META dropdown (now four entries: myers / vscode / patience / difflib), and in Command.get_config's default. The autojunk config option's comment was updated to mention that Myers also does not support autojunk.
* change: differ._fancy_replace now uses InlineMyersSequenceMatcher (not MyersSequenceMatcher) when diff_algorithm is 'myers'. InlineMyersSequenceMatcher is the Myers variant Meld designed specifically for character-level (inline) diffing: its preprocessing pass uses 3-element k-mers instead of single elements, which makes the preprocessing effective on character sequences (where single characters are rarely unique -- 'a' appears everywhere, so 1-element preprocessing would discard almost nothing). The base MyersSequenceMatcher's 1-element preprocessing is appropriate for the main line-level diff (where each line is usually unique enough), but ineffective for character-level diffing. Benchmarks show InlineMyersSequenceMatcher is 2-4x faster than MyersSequenceMatcher on medium/long lines for character-level diffing, and produces more meaningful character-level diffs. The main line-level diff path (Differ.compare) still uses MyersSequenceMatcher. PatienceSequenceMatcher and DefaultSequenceMatcher are unchanged in _fancy_replace.

2026.08.06 (by @badrelmers)
+ add: new "vscode" diff algorithm (default), ported from VS Code's diff implementation (https://github.com/microsoft/vscode/tree/main/src/vs/editor/common/diff). Uses dynamic programming (O(MN) LCS with equality scoring and consecutive-diagonal bonus) for files with fewer than 1700 combined lines, and Myers diff (O(ND) with snake optimization) for larger files. Also includes VS Code's heuristic post-processing: optimizeSequenceDiffs (shift/join adjacent diffs to natural boundaries) and removeVeryShortMatchingLinesBetweenDiffs (absorb tiny equal blocks between large changes). The equality scoring (1 + log(1+line_length) for exact matches, 0.99 for whitespace-only matches) and consecutive-diagonal bonus are the key innovations that make this algorithm produce correct alignment on files with many duplicated lines where both patience diff and difflib fail. The "vscode" algorithm is now the default; "patience" and "difflib" remain available as alternatives.
* change: replaced the boolean "use_patience_diff" config option with a new "diff_algorithm" option (frm='str2s', dct=[('vscode','VS Code (DP + Myers)'), ('patience','Patience Diff'), ('difflib','Python difflib stdlib')]) that exposes a real dropdown in the config dialog. The default is now 'vscode' (previously the boolean defaulted to false, i.e. difflib, then later 'patience'). differ.py reads self.diff_algorithm and selects VSCodeSequenceMatcher / PatienceSequenceMatcher / DefaultSequenceMatcher accordingly.
